# Bito — план функций

> [!abstract] Суть
> Онлайн-дурак на виртуальную валюту. Игроки садятся за стол со ставкой, проигравший платит, победители делят банк. Рейтинга (Elo) нет. Настоящих денег нет.

## 1. Принятые решения

| Решение | Значение |
|---|---|
| Рейтинг Elo | **не делаем** |
| Игра | на ставки виртуальной валюты |
| Реальные деньги | **нет**, только виртуальная валюта |
| Минимальная ставка | 100 |
| Комиссия стола | 5% (можно поднять до 10%) |
| Стартовый баланс | выдаётся при регистрации |
| Подачка | если баланс меньше 100 |
| Лидерборд | делаем позже, низкий приоритет |

## 3. Экономика (ядро проекта)

### 3.1. Параметры

Значения черновые, держим их константами в одном месте и меняем без переделки логики.

| Параметр | Значение |
|---|---|
| Минимальная ставка | 100 |
| Стартовый баланс | 1000 (предложение) |
| Комиссия | 5% от ставки проигравшего |
| Порог подачки | баланс меньше 100 |
| Размер подачки | пополнение до 500, не чаще раза в час (предложение) |

### 3.2. Правила выплат

1. При посадке за стол ставка **блокируется** (списывается с баланса).
2. По итогам партии проигравший теряет свою ставку.
3. Из ставки проигравшего вычитается комиссия.
4. Остаток делится между победителями **по местам**: кто вышел первым, получает больше.
5. Каждый победитель дополнительно получает **свою ставку обратно**.

Доля места `i` среди `m` победителей:

```
доля(i) = (m - i + 1) / (m * (m + 1) / 2)
```

| Победителей | Доли по местам |
|---|---|
| 1 | 100% |
| 2 | 67% / 33% |
| 3 | 50% / 33% / 17% |
| 4 | 40% / 30% / 20% / 10% |

> [!note] Почему не «процент от всего банка»
> Первоначальная идея: победители делят весь банк по процентам. Проблема в том, что последний из победителей может получить **меньше своей ставки**. Например, банк 2000 (4 игрока по 500), третье место забирает 18% = 360. Он не проиграл, но ушёл в минус 140. Это нелогично. Поэтому каждый победитель получает свою ставку обратно, а делится только ставка проигравшего.

### 3.3. Пример: 4 игрока, ставка 500

| Игрок | Результат | Итог |
|---|---|---|
| Проигравший | потерял ставку | **−500** |
| Комиссия (5% от 500) | | 25 |
| Пул для победителей | 500 − 25 | 475 |
| 1 место | 475 × 3/6 | **+238** |
| 2 место | 475 × 2/6 | **+158** |
| 3 место | 475 × 1/6 | **+79** |

Проверка: 238 + 158 + 79 − 500 = −25, то есть ровно комиссия. Деньги не появляются и не исчезают.

### 3.4. Крайние случаи

| Ситуация | Что происходит |
|---|---|
| Ничья (`isDraw`) | ставки возвращаются, комиссии нет |
| Игрок сдался | проигравший, платит ставку |
| Игрок отключился на 30 секунд | автоматическая сдача, платит ставку |
| Стол закрыт до старта | ставки возвращаются |
| Баланс меньше ставки стола | сесть за стол нельзя |
| Округление | целые числа, остаток уходит игроку на 1 месте |
| Несколько игроков вышли за один ход | порядок по месту за столом (предложение) |

> [!tip] Чтобы деньги не терялись
> Блокировка ставки и выплата проходят **в одной SQL-транзакции**. Каждое движение денег пишется в журнал `wallet_transactions`. Баланс всегда можно перепроверить суммой журнала.

### 3.5. Данные

```sql
wallet_transactions(id, user_id, amount, kind, game_id, created_at)
games(id, mode, deck_type, stake, started_at, finished_at)
game_players(game_id, user_id, place, payout)
```

`kind`: `stake_lock`, `stake_refund`, `win_payout`, `signup_bonus`, `top_up`, `purchase`.

## 5. Как делаем каждую функцию

### 4. Лобби-сокет
Сейчас `/ws` принимает только `room_id`, без него отвечает 400. Игрок вне стола не подключён. Добавляем специальную комнату «lobby» в `Hub`, куда игрок попадает при входе в лобби.
Даёт: общий чат, онлайн-статус друзей, приглашения, живое обновление списка столов вместо опроса.

### 5. Общий чат сервера
Сообщение отправляется в лобби-комнату и рассылается всем. История последних 50 сообщений хранится в памяти. Ограничение длины и частоты отправки.

### 6. Чат внутри стола
Готово: панель чата, облачка над игроками, быстрые фразы, анимированные эмодзи Noto. На бэкенде обрезка пробелов, лимит 200 символов и не чаще раза в 700 мс.

### 7. Друзья
Минимальная версия, потом онлайн и приглашения:

```sql
friendships(user_id, friend_id, status, created_at)  -- pending | accepted
```

| Метод | Назначение |
|---|---|
| `POST /friends/requests` | отправить заявку |
| `POST /friends/requests/{id}/accept` | принять |
| `DELETE /friends/{id}` | удалить или отклонить |
| `GET /friends` | список с онлайн-статусом |

Шаги: сначала REST без онлайна, потом статус через лобби-сокет, потом приглашение за стол.

### 8. История партий
Пишется из таблиц `games` и `game_players` (раздел 3.5). Показывает: когда, режим, ставка, место, выигрыш или проигрыш. Почти бесплатна после экономики.

### 10. Темы и рубашки карт
Тема это набор CSS-переменных под `data-theme`. Рубашка карт и сукно стола выбираются независимо от темы.

```css
:root[data-theme="dark"]   { --bg: #14161a; --accent: #e0b04a; }
:root[data-theme="light"]  { --bg: #f5f5f2; --accent: #b8860b; }
:root[data-theme="forest"] { --bg: #0f1a14; --accent: #8fbf6a; }
```

Хранение: сначала `localStorage`, потом поле в профиле на сервере.

### 11. Магазин косметики
Таблица `user_items(user_id, item_id)`. Покупка списывает валюту через `wallet_transactions` (`kind = purchase`). Предметы: темы, рубашки, сукно.

### 12. Лидерборд
Эндпоинт `GET /users/leaderboard`. Критерий пока не выбран (баланс, победы или заработок за неделю).

## 6. Реконнект

**Что есть**
- При обрыве соединения игроку даётся **30 секунд** (`disconnectGraceDur` в `room.go`)
- Остальные получают `player_disconnected`, при возврате `player_reconnected`
- Не вернулся за 30 секунд, значит **автоматическая сдача**
- Фронт (`useGameSocket.ts`) сам переподключается и показывает статус «Переподключаемся…»

**Чего нет**
- [ ] Если игрок закрыл вкладку или ушёл в лобби, нет способа узнать, что у него идёт партия. Нужно: `GET /me/active-table` и плашка «Вернуться за стол» в лобби.
- [ ] Один аккаунт может открыть два соединения или два стола. Со ставками это недопустимо (см. раздел 7).
- [ ] Выплата при автосдаче по таймауту: убедиться, что она проходит через ту же транзакцию, что и обычный конец партии.

## 7. Идеи, которые стоит добавить

> [!important] Нужны, потому что в игре появляются деньги

- [ ] **Один аккаунт, один активный стол.** Иначе игрок сядет за два стола с одной ставкой.
- [ ] **Журнал транзакций.** Без него невозможно разобраться, куда делись деньги.
- [ ] **Тесты на инварианты денег:** сумма изменений балансов за партию равна минус комиссия.
- [ ] **Приватные столы** по ссылке или приглашению. Естественно сочетаются с друзьями.
